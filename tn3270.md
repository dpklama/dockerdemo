## 📄  Requirements Document – Cache‑Only, Multi‑Server, TLS‑Enabled TN3270 Client  

**Purpose** – This document describes, in a precise, LLM‑friendly way, everything that must be built to obtain a **single Maven module** that provides a **cache‑only TN3270 client** with:

* support for **multiple logical servers** (each can use plain TCP or TLS)  
* **connection pooling** per server (bounded, idle‑eviction, health‑check)  
* a **pure‑Java DSL** for declarative transaction definition  
* a **high‑level Session façade** that adds timeout, single automatic retry, interceptor chaining, optional result‑caching, and metric collection  
* **JSON/YAML files** for screen templates and for server configuration  

All code must compile with **Java 21**, be **thread‑safe**, and include **JUnit‑Jupiter + Mockito** unit tests. The project must be buildable with:

```bash
cd tn3270-client
mvn clean package
```

---

### 1️⃣  High‑Level Goals

| Goal | Success Criterion |
|------|--------------------|
| **Cache‑only screen handling** | Screens are never parsed at runtime; a `TemplateCache` loaded once from JSON files is used for all matching. |
| **Multi‑server support** | An arbitrary number of logical servers can be defined in a single configuration file; each gets its own connection pool. |
| **TLS on demand** | When the server definition sets `tlsEnabled:true` the client creates an `SSLSocket`; otherwise a plain `Socket`. |
| **Connection pooling** | Each server has a bounded pool (`maxSize`), a minimum idle count (`minIdle`), idle‑eviction, health‑check (`AID.NONE` ping), creation‑retry/back‑off, and metric callbacks. |
| **Fluent DSL** | Users build an immutable `Transaction` via `TransactionDsl.transaction("name")…build()`. |
| **Session façade** | `Session.execute(tx, timeout)` runs a transaction, applies a per‑transaction timeout, performs **one automatic retry** on transport‑level failures, runs interceptors, updates optional result cache, and records metrics. |
| **Testing** | At least one unit test per major package, all passing with Maven’s default surefire plugin. |
| **Zero external code‑gen tools** | The final artefact is plain Java source; no annotation processors, Lombok, etc. |

### 4️⃣  Functional Requirements – Detailed

#### 4.1  Template Cache (package `template`)

* **`TemplateCache`** – immutable class constructed from a collection of `ScreenTemplate`s.  
  * `Optional<ScreenTemplate> findByChecksum(String checksum)`  
  * `Optional<ScreenTemplate> findByName(String name)`  

* **`ScreenTemplate`** – JSON model with fields:  
  * `name` (String)  
  * `checksum` (String, MD5 hex)  
  * `fields` (list of `FieldTemplate`)  
  * `staticTexts` (list of String)  

* **`FieldTemplate`** – name, row, column, length (all integers).  

* **`TemplateLoader`** – scans a folder (`templates/`), reads every `*.json` file with Jackson, builds a `TemplateCache`.  

#### 4.2  Core Engine (package `core`)

| Class | Public API | Behaviour |
|-------|------------|-----------|
| **`TN3270Config`** | Builder (`builder()` → setters → `build()`) | Holds TLS flag, connect/read timeouts, strict‑template‑mode flag, `TelnetNegotiator`, `EBCDICCodec`. |
| **`TN3270Session`** | `static TN3270Session connect(String host, int port, TN3270Config cfg) throws IOException`<br>`void setTemplateCache(TemplateCache cache)`<br>`void start()`<br>`void sendCommand(AIDCommand cmd)`<br>`String lastScreenChecksum()`<br>`void close()` | *TLS*: if `cfg.tlsEnabled()` → `SSLSocket`, else `Socket`.<br>*Negotiation*: perform telnet negotiation using the supplied negotiator.<br>*Read loop*: a **virtual thread** reads frames (2‑byte length prefix) and puts raw bytes into a `BlockingQueue<byte[]>`.<br>*Strict mode*: first received screen must match a template; otherwise throw `TemplateMismatchException`.<br>*Thread‑safety*: `sendCommand` synchronized. |
| **`Checksum`** | `static String calculateMD5(byte[] data)` | Returns lower‑case 32‑char hex MD5. |
| **`ScreenScraper`** (interface) | `Screen waitForScreen(String templateName, Duration timeout)` | Implemented by `TemplateBasedScraper`. |
| **`TemplateBasedScraper`** | Constructor receives `TN3270Session` and `TemplateCache`. Implements `ScreenScraper`. | Polls the inbound queue, computes checksum, matches a `ScreenTemplate`, and returns a `ScreenImpl`. |
| **`Screen`** (interface) | `void writeField(String fieldName, String value)`<br>`String readField(String fieldName)`<br>`void press(AID aid)`<br>`boolean containsStaticText(String text)` | `ScreenImpl` uses field offsets, EBCDIC codec, and sends a placeholder Write command (TODO comment). |
| **`TransactionExecutor`** | Constructor `(TN3270Session session)`<br>`Map<String,String> execute(Transaction tx) throws TemplateMismatchException, TransactionExecutionException` | For each `Step`: wait for screen via `TemplateBasedScraper`, then execute all `Operation`s in order. Returns an **unmodifiable** map of `ReadOp` results (`resultKey → value`). |

#### 4.3  DSL (package `dsl`)

* **Entry point** – `TransactionDsl.transaction(String name)` returns a `TransactionBuilder`.  
* **Fluent methods** –  

  * `.onScreen(String templateName)` → `StepBuilder`  
  * `.setField(String field, String value)`  
  * `.press(AID aid)`  
  * `.readField(String field, String resultKey)`  
  * `.assertStatic(String staticText)`  
  * `.build()` – returns an immutable `Transaction`.  

* **Model** (`dsl.model`):  

  * `Transaction` – name + immutable list of `Step`.  
  * `Step` – template name + immutable list of `Operation`.  
  * `sealed interface Operation` – permits four concrete records:  

    * `WriteOp(String fieldName, String value)`  
    * `ReadOp(String fieldName, String resultKey)`  
    * `PfOp(AID aid)`  
    * `AssertOp(String staticText)`  

* All model objects must be **immutable** (final fields, no setters).

#### 4.4  Connection Pool (package `pool`)

* **`TN3270Pool`** – static factory  

  ```java
  public static TN3270Pool create(Config cfg,
                                  TemplateCache cache,
                                  MetricCollector metrics);
  ```

* **`Config`** (inner record) fields:  

  `String host; int port; TN3270Config tn3270Config; int maxSize; int minIdle;
   Duration maxWaitTime; Duration idleTimeout; Duration validationTimeout;
   int creationRetryAttempts; Duration creationRetryBackoff;`

* **Public methods**  

  * `PooledSession acquire() throws TimeoutException, InterruptedException` – blocks up to `maxWaitTime`. Before returning, performs a health‑check by sending `AID.NONE` and waiting `validationTimeout`.  
  * `void close()` – graceful shutdown (stop evictor, creator, close idle sessions).  

* **`PooledSession`** (inner class, implements `AutoCloseable`)  

  * `TN3270Session session()` – the raw socket.  
  * `void release()` – mark as healthy and return to idle queue.  
  * `void releaseUnhealthy()` – discard (close underlying socket).  
  * `close()` → `release()`.  

* **Behaviour details**

  * **Semaphore** limits total sessions to `maxSize`.  
  * **Idle queue** (`LinkedBlockingQueue<PooledSession>`) holds ready‑to‑borrow sessions. At construction, the pool pre‑creates `minIdle` sessions.  
  * **Scheduled evictor** runs every `idleTimeout / 2` (or a fixed 30 s) and discards sessions idle longer than `idleTimeout`.  
  * **Async creator** runs in a single‑thread executor; on demand it creates a new `TN3270Session` using `TN3270Session.connect`. If creation fails, it retries up to `creationRetryAttempts` with a pause of `creationRetryBackoff`.  
  * **MetricCollector** callbacks are invoked for every event (see Section 4.5).  
  * **Shutdown** – `close()` stops the evictor, shuts down the creator executor, and closes all idle sessions; any in‑flight session gets a short grace period (e.g., 5 s) before forced close.

    void connectionBorrowed();

* **Implementations** (both in `api`):

  * `MicrometerMetricCollector` – wraps Micrometer `Counter`s (implementation may be minimal but must compile).  

#### 4.6  High‑Level Session API (package `api`)

```java
public interface Session extends AutoCloseable {
    Map<String,String> execute(Transaction tx, Duration timeout)
            throws TemplateMismatchException,
                   TransactionExecutionException,
                   SessionException;

    default Map<String,String> execute(Transaction tx)
            throws TemplateMismatchException,
                   TransactionExecutionException,
                   SessionException {
        return execute(tx, Duration.ofMillis(Long.MAX_VALUE));
    }

    @Override void close();   // returns the pooled connection to the pool
}
```

* **`SessionException`** – checked, wraps `IOException`, `TimeoutException`, or any transport‑level problem.  

* **Error handling** (see Section 4.11).  

#### 4.7  Session Implementation (`impl`)

* **`SessionFactory`** – constructed with a `TN3270Pool`, a `List<SessionInterceptor>` (may be empty), and a `MetricCollector`.  
  * `Session create()` – acquires a `PooledSession` from the pool, wraps it in a `PooledSessionAdapter`.  

* **`PooledSessionAdapter`** – implements `Session`.  

  1. **Bind** the underlying `TN3270Session` to `TemplateBasedScraperHolder` (ThreadLocal) so that the scraper can locate the correct session.  
  2. **Run before‑interceptors** (`Transaction beforeExecute(Transaction)`). Allow each interceptor to replace the transaction.  
  3. **Execute** the transaction using `TransactionExecutor` inside a `CompletableFuture` with `orTimeout(timeout)`.  
  4. **On `SessionException` or unchecked runtime exception** – perform **one automatic retry**: discard the current `PooledSession` (`releaseUnhealthy()`), acquire a fresh one, and re‑execute the (possibly transformed) transaction. If the retry also fails, propagate the exception.  
  5. **Populate `ResultCache`** (cleared before each execution) with every `ReadOp` value.  
  6. **Run after‑interceptors** (`Map<String,String> afterExecute(Transaction, Map<String,String>)`).  
  7. **Record metrics** (`connectionReturned` on success, `connectionDiscarded` on failure).  
  8. `close()` simply calls `pooledSession.release()`.  

* **`ResultCache`** – thread‑safe `ConcurrentHashMap<String,String>` with `put`, `get`, `clear`, `snapshot()` (unmodifiable copy).  

* **`SessionInterceptor`** – functional interface (see Section 4.4).  

#### 4.8  Configuration (package `config`)

* **`ServersConfig`** – root POJO: `List<ServerConfig> servers`.  
* **`ServerConfig`** – fields:  

  * `String name` – logical name used by the client.  
  * `String host`  
  * `int port`  
  * `boolean tlsEnabled`  
  * `LoginCredentials login` (nested static class – `user`, `password`).  
  * `PoolConfig pool` (nested static class – mirrors `TN3270Pool.Config`).  

* **`ConfigLoader`** – static method  

  ```java
  public static ServersConfig load(Path path) throws IOException
  ```

  * Detect file extension (`.yaml` / `.yml` → use `ObjectMapper` with `YAMLFactory`; otherwise plain JSON).  
  * Deserialize to `ServersConfig`.  
  * Resolve any `${VAR}` placeholders in passwords (or other strings) by replacing them with `System.getenv(VAR)`. If the environment variable is missing, leave the placeholder unchanged.  

* **No external configuration framework** – plain Jackson only.

#### 4.9  Registry & Facade (package `registry`)

* **`ServerRegistry`** – constructor  

  ```java
  public ServerRegistry(ServersConfig cfg,
                        TemplateCache sharedCache,
                        MetricCollector metrics)
  ```

  * For each entry in `cfg.servers()` creates a dedicated `TN3270Pool` using the entry’s `PoolConfig` and a `TN3270Config` where `tlsEnabled` is taken from the entry, `strictTemplateMode=true`, default timeouts (e.g., 5 s connect, 5 s read).  
  * Stores pools in a `ConcurrentHashMap<String, TN3270Pool>` keyed by `ServerConfig.name`.  
  * Provides `SessionFactory getSessionFactory(String logicalName)` – throws `IllegalArgumentException` if unknown.  
  * Implements `AutoCloseable` – `close()` iterates over all pools and calls `pool.close()`.  

* **`MultiServerSessionFactory`** – thin façade:

  ```java
  public final class MultiServerSessionFactory implements AutoCloseable {
      private final ServerRegistry registry;
      public MultiServerSessionFactory(ServerRegistry registry) { this.registry = Objects.requireNonNull(registry); }
      public SessionFactory forServer(String logicalName) { return registry.getSessionFactory(logicalName); }
      @Override public void close() { registry.close(); }
  }
  ```

#### 4.10  Error‑Handling Policy (global)

| Exception Type | When Thrown | Action by `Session` |
|----------------|------------|---------------------|
| `TemplateMismatchException` | Screen checksum not in cache (or static‑text mismatch) | Propagate; **no retry**; session stays healthy. |
| `TransactionExecutionException` | Write/read/assert failure on a matched screen | Propagate; **no retry**; session stays healthy. |
| `SessionException` (IO, timeout, unexpected) | Transport‑level failure | **One automatic retry** (discard current pooled session, borrow a fresh one, re‑execute). If retry also fails → propagate. |
| `TimeoutException` (pool acquire or per‑transaction timeout) | Wait exceeds configured limit | Propagate directly; session not borrowed (or already returned). |
| `InterruptedException` | Thread interrupted while waiting | Propagate; re‑set interrupt flag. |
| unchecked `RuntimeException` | Programming bug or unexpected runtime error | Treat as **unhealthy** → discard the pooled session, propagate. |

All exceptions must be logged with a clear message containing:

```
[tn3270] Transaction='${txName}' Screen='${screenName}' – ${ExceptionClass}: ${message}
```

#### 4.11  Testing Requirements

* **One test class per major package** (`api`, `core`, `dsl`, `pool`, `impl`, `scraper`, `template`, `config`, `registry`).  
* Use **JUnit‑Jupiter** (`@Test`) and **Mockito** for mocks.  
* Sample test ideas (must compile and pass):  

  * **DSL** – verify that `TransactionDsl.transaction("T")…build()` produces a `Transaction` whose name, steps, and operations match the builder calls.  
  * **Checksum** – confirm that `Checksum.calculateMD5("abc".getBytes())` equals the known MD5 value.  
  * **TemplateCache** – load dummy templates and assert that `findByChecksum` and `findByName` work.  
  * **TN3270Session** – mock a socket, verify that `sendCommand` writes the correctly prefixed byte array, and that `lastScreenChecksum` returns the checksum of the latest matched screen.  
  * **TransactionExecutor** – mock `TemplateBasedScraper` to return a fake `Screen`; ensure that a transaction with a `ReadOp` returns the expected map.  
  * **TN3270Pool** – create a pool with `maxSize=2`, acquire three sessions in parallel, assert that the third call blocks/times‑out after `maxWaitTime`. Verify that idle eviction discards sessions after `idleTimeout`.  
  * **PooledSessionAdapter** – mock a `TN3270Session` that throws `SessionException` on first call; assert that the adapter retries once and succeeds on the second attempt. Validate that interceptors are invoked in the correct order.  
  * **ConfigLoader** – load the provided `servers.yaml`; assert that placeholders `${BANK01_PWD}` are replaced with the corresponding environment variable (set a test env var before loading).  

* All tests must be placed under `src/test/java/com/example/tn3270/` and run with Maven’s default `surefire` plugin (no extra configuration needed).

#### 4.13  README – Usage Example (must be included)

```java
// 1️⃣ Load the server configuration (YAML or JSON)
ServersConfig serversCfg = ConfigLoader.load(
        Paths.get("src/main/resources/servers.yaml"));   // or .json

// 2️⃣ Load the shared screen‑template cache
TemplateCache tmplCache = TemplateLoader.load(
        Paths.get("src/main/resources/templates"));

// 3️⃣ Choose a metric implementation (no‑op or Micrometer)
MetricCollector metrics = new MicrometerMetricCollector(); // or MetricCollector.NO_OP

// 4️⃣ Build the registry and the multi‑server façade
try (ServerRegistry registry = new ServerRegistry(serversCfg, tmplCache, metrics);
     MultiServerSessionFactory msFactory = new MultiServerSessionFactory(registry)) {

    // Obtain a SessionFactory for the logical server “BANK01”
    SessionFactory bankFactory = msFactory.forServer("BANK01");

    // Define a transaction with the DSL
    Transaction loginTx = TransactionDsl.transaction("BankLogin")
            .onScreen("login")
                .setField("USER_ID", "BANKUSER")
                .setField("PASSWORD", "Secret123")
                .press(AID.ENTER)
                .readField("WELCOME", TransactionDsl.into("welcome"))
            .build();

    // Execute the transaction
    try (Session s = bankFactory.create()) {
        Map<String,String> out = s.execute(loginTx, Duration.ofSeconds(30));
        System.out.println("Welcome message: " + out.get("welcome"));
    }

    // Example for a second logical server (HR02) – same pattern
    SessionFactory hrFactory = msFactory.forServer("HR02");
    // …build and run HR‑specific transaction…
}
```

Explain that the `try‑with‑resources` blocks automatically return connections to the pool, and that closing `msFactory` shuts down **all** pools.
